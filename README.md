## 它解决什么问题

「高新技术企业认定」满分 100 分、**>70 分才达标**（整数口径 ≥71）。但网上流传的评分口径
大量是**已废止的 2008 版**，按那套算会得出错误结论，误导企业准备错方向。

本系统实现的是**现行国科发火〔2016〕32 号 + 2016 版工作指引**的国家版规则，
并且刻意区分两个总分的用途：

| 总分 | 算法 | 用途 |
|---|---|---|
| **保守总分** | 各评分项取政策区间**下界**之和 | **判定是否达标的唯一依据**（>70） |
| **乐观总分** | 各评分项取区间**上界**之和 | 仅作冲刺目标，**不能用来判断达标** |

这个区分是核心设计：拿乐观分当结论，等于自己骗自己。

## 四项指标（合计 100）

| 指标 | 上限 | 关键口径 |
|---|---:|---|
| 知识产权 | 30 | Ⅰ/Ⅱ 类分开；Ⅱ 类**仅限使用一次**；未授权不计分 |
| 科技成果转化 | 30 | 年平均数 = 总数 ÷ **实际经营年数**；同一成果多形式转化只计 1 项 |
| 研发组织管理 | 20 | 4 组档位 6 + 6 + 4 + 4；制度类材料补齐即可提档，**性价比最高** |
| 企业成长性 | 20 | 三态算法：满 3 年两段公式 / 满 2 年单段降维 / 刚满 1 年 **0 分** |

另有 **8 条一票否决项**（成立年限、知识产权归属、研发费用占比、科技人员占比、
高新技术产品收入占比、创新能力评价、安全质量事故、严重违法）——任一不满足即**不能认定**，
必须先解决再谈打分。

> ⚠️ 网上流传的「组织管理 30 分、成果转化 20 分、净资产 9 + 销售收入 7 + 年平均利润率 4」
> 是**已废止的 2008 版**口径，本系统不采用。

## 快速开始

**方式一：在线用** —— 打开 https://hitech-score.app.workbuddy.host/ ，手机/平板/电脑均可。

**方式二：本地跑** —— 双击 `outputs/高企评分自评系统/index.html`。
零依赖、零安装、无需联网、无需后端。

**方式三：装成 App** —— 这是 PWA：Chrome/Edge 右上角菜单「安装应用」，
iPhone 用 Safari「添加到主屏幕」。装完**断网也能用**。

> 为什么是 PWA 而不是小程序：政策常变，原生 App 每次改规则都要重新打包 + 等审核；
> PWA 改规则即时生效，也不需要应用商店。

## 规则与代码解耦

**改政策只改规则包，不用碰代码。**

```
rules/policy.json          规则包（档位、上限、边界条件、政策文案、免责声明）
assets/rule-engine.js      规则引擎（配置化规则 + 三态成长性算法，可单独用 Node 跑）
assets/app.js              交互、渲染、导出、本地存储、规则包更新
```

三种更新方式：

| 方式 | 场景 |
|---|---|
| **远端更新** | 政策调整，所有用户立刻用上新规则 —— 换掉服务器上的 `policy.json`，用户点「检查远端更新」即生效 |
| **手动导入** | 单机使用 / 临时改规则 —— 第 ⑦ 区「导入规则包」 |
| **改代码基线** | 需要长期固化 —— 编辑 `rule-engine.js` 顶部 `POLICY` 配置对象 |

规则包关键字段：`policy_version`、`pack_updated_at`、`ip.items[].bands`、
`transform.bands`、`rdmgmt.ratio_bands`、`growth.bands`、`precheck`。

**切换规则包不会影响已填写的填报数据。**

## 数据安全

- 所有计算在**本地浏览器**完成，**不上传任何服务器**。
- 填报数据存 `localStorage`，可导出 JSON 长期保存 / 导入恢复。
- 企业财务与知识产权属敏感数据，导出文件请自行保管。
- 「生成分享链接」会把数据编码进 URL —— **只发给可信对象**。

## 导出能力

| 功能 | 说明 |
|---|---|
| 导出 PDF | 调打印对话框另存为 PDF，A4 排版已优化，含报告抬头与免责声明 |
| 导出 Excel | 5 个工作表：评分明细 / 知识产权台账 / 成果转化台账 / 整改建议 / 资格预检 |
| 备份 JSON | 长期保存，可随时导入恢复 |
| 分享链接 | 把填报数据编码进 URL，发给顾问复现 |

## 项目结构

```
├── outputs/
│   ├── 高企评分自评系统/          ← 可运行的 PWA
│   │   ├── index.html
│   │   ├── assets/{app.js, rule-engine.js, styles.css}
│   │   ├── rules/policy.json     ← 规则包
│   │   ├── manifest.webmanifest
│   │   ├── sw.js
│   │   ├── icons/
│   │   └── 使用说明.md            ← 完整使用手册
│   ├── 00-全栈系统交付全案.md      ← 团长整合（执行摘要、政策口径总表、20 项终裁）
│   ├── phase1-需求与平台选型报告.md
│   ├── phase1-产品定义方案-PRD.md  （946 行，含附录裁决）
│   ├── phase1-技术研发方案.md
│   ├── phase2-测试保障方案.md
│   ├── phase3-上线发布方案.md
│   ├── phase4-运维保障方案.md
│   └── phase5-运营增长方案.md
└── .gitignore                    ← 排除 WorkBuddy 运行时元数据
```

`outputs/` 下 8 份文档是用「全栈智造专家团」5 阶段工作流（完整模式）产出的，
从需求选型一路到运营增长，保留下来是因为它们记录了口径决策的**推导过程**，
而不只是结论。
