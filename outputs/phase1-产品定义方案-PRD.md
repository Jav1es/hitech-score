## 1. 背景

1. 高新技术企业认定可享 15% 企业所得税优惠与地方政府补贴，但创新能力评价涉及 **4 大指标、10+ 评分子项、7 项一票否决前置条件**，企业普遍依赖 Excel 手工核算，口径易错、边界条件（Ⅱ类知识产权仅用一次、同一成果只计一项、负增长率记 0 分等）极易踩坑。
2. 现有市场方案要么是"静态打分表模板"（无计算、无台账管理），要么是"咨询顾问人工服务"（单价 3000~20000 元、周期 3~7 天），缺少一款**在线、可复用、可模拟、可导出**的标准化工件。
3. 目标用户（拟申报/复审的科技型中小企业项目申报负责人，以及代理申报的科技服务机构）的核心诉求是：**先知道"能不能报"，再知道"现在多少分"，最后知道"差多少分、补什么"**。
4. 依据团长确认结论：目标用户为 R1/R2/R3 三类，平台形态为 PC Web + 移动响应式，V1.0 交付自评闭环。

## 2. 目标

### 2.1 一句话定位

> **「高企认定创新能力自评与达标诊断工具」—— 10 分钟完成资格预检 + 四项指标打分，输出可提交的分数诊断与整改建议报告。**

### 2.2 三点核心价值

| # | 价值 | 用户可感知的表述 |
|---|------|------------------|
| V1 | **算得准** | 政策口径内置、边界条件自动兜底（Ⅱ类去重 / 同一成果只计一项 / 负增长率 / 首年为 0 / 第二年为 0），不靠人肉记规则 |
| V2 | **说得清** | 每一项分数可下钻到政策原文条款 + 佐证材料清单，顾问可直接拿去和客户对齐 |
| V3 | **知道补什么** | 输出"距离 71 分还差 X 分 → 建议补 Y 项软著 / 提升 Z 项"的**排序整改清单**，并支持多方案沙盘对比 |

### 2.3 业务目标与成功度量

| 指标类型 | 指标 | 目标值 | 统计口径 | 数据来源 |
|----------|------|--------|----------|----------|
| **北极星** | 周有效自评完成企业数（WCSO） | 上线第 4 周单周 ≥ 120；上线 12 周累计 ≥ 800 | 统计周期内完成四项指标全部填写 **且** 生成 ≥1 份诊断报告的**去重企业数**（按 `org_id` 去重，游客会话不计） | 埋点 `report_generate` + `scoring_records.status=completed` |
| 辅助 | 注册转化率 | ≥ 35% | `register_success` 去重用户数 / `landing_view` 去重访客数 | 埋点 |
| 辅助 | 建档完成率 | ≥ 70% | 完成 `org_create` 数 / 进入建档页 UV | 埋点 |
| 辅助 | 资格预检通过率 | 观测值（不做目标） | `precheck_submit` 中 `pass=true` 占比 | 埋点 |
| 辅助 | **四项打分完成率（核心漏斗）** | ≥ 55% | 四模块全部 `score_module_complete` 的会话数 / 通过预检的会话数 | 埋点 |
| 辅助 | 报告生成率 | ≥ 60% | `report_generate` / 打分完成数 | 埋点 |
| 辅助 | 导出率 | ≥ 45% | `export_pdf` / `report_generate` | 埋点 |
| 辅助 | 次月回访率 | ≥ 25% | 次月仍产生 ≥1 次 `scoring_open` 的老用户占比 | 埋点 |
| 辅助 | 留资/咨询转化（V1.1） | ≥ 8% | 提交联系方式数 / 报告生成数 | 埋点 |
| 质量 | P0 缺陷数 | 0 | 上线前回归 P0 用例全通过 | 测试报告 |

## 3. 用户故事

### 3.1 角色定义

| 角色 | 代号 | 画像 | 核心诉求 | 使用端 |
|------|------|------|----------|--------|
| 企业项目申报负责人 | R1 | 科技型中小企业，1~3 人负责申报，缺乏政策细节经验 | 快速判断"能不能报 / 差多少分 / 怎么补" | PC 为主，手机查看 |
| 研发 / 财务负责人 | R2 | 提供专利台账、转化清单、三年财务数据 | 录入不痛苦、口径清楚、能复用历史数据 | PC |
| 科技服务机构顾问 | R3 | 会计师事务所、知产代理、申报咨询，同时服务 5~50 家企业 | 批量建档、方案对比、报告可交付给客户 | PC |

### 3.2 场景 — 痛点 — 解决方案

| 角色 | 场景 | 痛点 | 解决方案 |
|------|------|------|----------|
| R1 | 年初评估今年能否申报 | 不知道 7 项一票否决条件，材料准备一半才发现"研发费用占比不够" | **F-04 资格预检**：7 项逐条判定，任一不通过即阻断并给出原因与补救路径 |
| R1 | 手工在 Excel 里算分 | Ⅱ类知识产权只能用一次、同一成果只计一项等规则记不住 | **F-05/F-06**：台账式录入，规则内置，重复项自动去重并提示 |
| R2 | 提供三年财务数据 | 净资产增长率公式复杂（1/2×(二/一 + 三/二)−1），负值/首年为 0 不知怎么处理 | **F-08**：输入三年数据自动计算，边界条件自动兜底并弹提示文案 |
| R1 | 拿到分数后不知道怎么提分 | 只知道"59 分"，不知道补什么最划算 | **F-10 差距诊断**：按"单位投入可提分幅度"排序给出整改清单 |
| R3 | 给客户做申报方案 | 客户问"如果我们再买 3 个软著能到几分" | **F-18 多方案对比**（V1.1）：克隆方案 → 改参数 → 并排对比 |
| R3 | 交付成果给客户 | 需要可打印、带政策依据的正式文档 | **F-13 PDF 导出** + **F-12 政策原文对照** |
| R1/R3 | 政策条款对不上 | 顾问说"这项能拿 8 分"，客户不信 | 每个评分项右侧固定展示政策原文锚点 |

## 7. 评分规则的产品化设计

### 7.1 总体原则：区间评分 + 保守/乐观双轨

政策条文对多项指标给出的是**分值区间**（如"25-30 分"）。产品不做单点臆断，而是：

1. 每项评分结果 = `[下限, 上限]` 区间；
2. 用户在全局三选一取值策略：**保守（取下限，默认）/ 稳健（取中值）/ 乐观（取上限）**；
3. 展示**保守总分**（用于达标判定）与**乐观总分**（冲刺目标）；
4. 达标判定：`保守总分 > 70`（整数口径即 ≥ 71 分）。

```python
# 取值策略
def pick(band: tuple[int, int], strategy: str = "conservative") -> float:
    lo, hi = band
    return {"conservative": lo,
            "balanced": round((lo + hi) / 2, 1),
            "optimistic": hi}[strategy]
```

### 7.4 客观项：企业成长性（≤20，基线已给）

```python
def growth_rate(v1: float, v2: float, v3: float, biz_years: int = 3) -> float:
    """净资产增长率 / 销售收入增长率（同一公式，工作指引口径）"""
    if biz_years <= 1:          # 刚满一年
        return 0.0
    if v2 == 0:                 # 第二年末为 0 → 0 分
        return 0.0
    if biz_years == 2 or v1 == 0:   # 第一年末为 0 或经营两年 → 按后两年
        r = v3 / v2 - 1
    else:
        r = 0.5 * (v2 / v1 + v3 / v2) - 1
    return max(r, 0.0)          # 负值为 0

def growth_band(r: float) -> tuple[int, int]:
    if r <= 0:   return (0, 0)
    if r >= 0.35: return (9, 10)
    if r >= 0.25: return (7, 8)
    if r >= 0.15: return (5, 6)
    if r >= 0.05: return (3, 4)
    return (1, 2)               # >0

# 示例：第一年 100，第二年 120，第三年 160
r = growth_rate(100, 120, 160)          # 0.5*(1.2 + 1.3333) - 1 = 0.2667
assert growth_band(r) == (7, 8)
# 边界
assert growth_rate(0, 100, 150) == 0.5          # 第一年末为 0 → 按后两年
assert growth_rate(100, 0, 150) == 0.0          # 第二年末为 0 → 0 分
assert growth_rate(200, 100, 150) == 0.0        # 负值 → 0
assert growth_rate(100, 120, 160, biz_years=1) == 0.0   # 刚满一年
```

QUALIFIED_THRESHOLD = 70.0      # 政策：达到 70 分以上（不含 70 分）

    return total > QUALIFIED_THRESHOLD

def gap_to_qualified(total_conservative: float) -> int:
    """整数计分口径下，达标最低分为 71"""
    return max(0, math.floor(QUALIFIED_THRESHOLD + 1 - total_conservative))

def uplift_space(items: dict[str, tuple[int, int]]) -> list[dict]:
    """items: {评分项code: (当前下限, 该项满分上限)} → 按可提分幅度降序"""
    out = [{"code": k, "delta": hi - lo} for k, (lo, hi) in items.items()]
    return sorted(out, key=lambda x: -x["delta"])

### 10.3 敏感数据处理

| 数据 | 级别 | 处理措施 |
|------|------|----------|
| 统一社会信用代码、三年财务数据、研发费用 | 高 | 传输 HTTPS(TLS1.2+)；存储列级 AES-256 加密；后台默认脱敏展示，需 `sensitive_view` 权限才可见明文；日志与埋点**绝不落**此类字段 |
| 企业名称 | 中 | 分享链接默认脱敏开关开启（显示"某科技有限公司"）；后台列表默认展示 |

| 游客会话数据 | 中 | 仅存浏览器本地 + 服务端临时键，30 天未登录自动清理 |

| 注销与删除 | — | 用户可自助注销，7 个工作日内完成物理删除并告知；埋点 `account_delete_request` 留痕 |
| 第三方共享 | — | **不向任何第三方共享或出售**用户填报数据；数据统计仅使用聚合脱敏结果 |

### 10.4 其他风控

- 用户承诺：建档页与报告页均要求勾选"本人承诺所填数据真实有效"；
- 频次限制：验证码 60s 重发、同 IP 每日 20 条；PDF 导出 5 次/分钟；
- 内容变更：规则版本升级后，老报告保持快照不变，新报告标注版本差异（V2.0 F-31）。

补充约束（写入规则引擎与 UI 提示）：

1. 加分项计入"知识产权"指标，且**加分后该指标总分不超过 30 分**（即 cap=30，截断在指标级而非子项级）。
2. 数量档位判定顺序：先看Ⅰ类（≥1项即 A 档），无Ⅰ类再看Ⅱ类数量；Ⅱ类按"仅限使用一次"规则，复审/重新认定时已用过的不计入。
3. 知识产权有多个权属人时，只能由一个权属人在申请时使用（系统按"本企业为唯一使用方"勾选校验）。
4. 专利有效性以获得授权证书（或授权通知书+缴费收据）为准；未授权不计入数量。

### A.2 R-02 成果转化"年平均数"除数口径（采纳你的默认，固化）

- 经营满 3 年：年平均数 = 近 3 年转化总数 ÷ 3。
- 经营不满 3 年：年平均数 = 转化总数 ÷ 实际经营年数（按完整会计年度数向下取整整年）。
- 实际经营期刚满 1 年：成长性指标按 0 分计算，但成果转化仍按实际转化数 ÷ 1 计算。
- UI 明示口径："本系统按您填写的实际经营年数 N 计算年平均数，公式为 转化总数 ÷ N"，并在输入页给出示例。

### A.3 R-03 年度口径（确认你 7.8 的定义，作为全团队唯一口径）

- 研发费用占比：近三个会计年度研发费用总额 ÷ 同期销售收入总额（三档：最近一年销售收入 <5000万(含)→5%；5000万~2亿(含)→4%；>2亿→3%）；境内研发费用占全部研发费用总额 ≥60%。
- 高新技术产品(服务)收入占比：申报前**一个年度**的高新收入 ÷ 同期总收入 ≥60%。
- 科技人员占比：申报前**一个年度**科技人员数 ÷ 当年职工总数 ≥10%（科技人员指直接从事研发和相关技术创新活动，以及专门从事上述活动的管理和提供直接技术服务的人员，累计实际工作时间在183天以上）。
- 成立时间：须注册成立一年以上（365个日历天数以上）。

### B.1 C2 账号体系时机 —— 采纳选型口径，但改为「渐进式留资」

### B.2 C4 经营满 2 年的成长性算法 —— PRD 方向对，但具体口径需修正

政策原文是"企业实际经营期不满三年的按实际经营时间计算"。关键认知：**增长率公式需要三个时点数据（第一年末 v1、第二年末 v2、第三年末 v3）才能算两段**；数据点不足时应降维，而不是套用"后两年"。

统一裁定（写入规则引擎，研发照此实现）：

- `biz_years >= 3`（经营满三年，有 v1/v2/v3）：g = 1/2 × (v2/v1 + v3/v2) − 1。
  - 若 v1 = 0：按后两年计算，g = v3/v2 − 1（政策明示）。
  - 若 v2 = 0：g = 0（政策明示）；同时 v1 = v2 = 0 时 g = 0。
- `biz_years == 2`（只有 v1/v2 两个时点）：**g = v2/v1 − 1**（单段降维），不套用 v3/v2。
  - 若 v1 = 0：无可用替代段，g = 0 并标记"数据不足，该项按 0 分计"。
- `biz_years == 1`（经营刚满一年）：成长性指标整体 **0 分**（政策明示）。
- 通用规则：任一增长率 < 0 → 按 0 分；分母 ≤ 0 → 该段不可用，按上述分支处理并在报告中给出黄色提示"该项因数据异常按 0 分计，请核对财务数据"。
- 净资产与销售收入两个指标各自独立按上述分支计算，互不牵连（一个 0 分不影响另一个）。
- 否决布尔参数：研发侧禁止使用 `full_three_years: bool`，必须用 `biz_years ∈ {1,2,3}` 三态。

### B.3 R-01c 知识产权获得方式区间重叠 —— 维持官方口径 1-6，用"实务参考值"解决引导问题

复核结论：官方《工作指引》表述为「有自主研发 1-6 分 / 仅有受让、受赠和并购等 1-3 分」，A 档上限 6、下界 1 属官方原文，规则配置**不得改为 3-6**，避免与政策文本冲突（专家有权在 1-6 内给分）。

用产品手段解决引导性，不改配置：

1. 规则配置保持 A 档 [1,6]、B 档 [1,3]。
2. 在该子项 UI 增加"实务参考"提示：自主研发（权属清晰、首次使用、与主营产品相关）实务常见 4-6 分；受让/受赠/并购 实务常见 1-2 分。
3. 报告中对该项按**两列**展示：`政策区间` 与 `实务参考值`（A 档实务值取 4，B 档取 2），并在报告尾部说明"实务参考值为经验值，仅供准备材料参考，最终由技术专家评定"。
4. 保守总分仍严格按政策区间下界计算（A、B 均为 1），保证不夸大；另设"实务预估总分"一列与之并列展示，两者均不能替代专家评审。
