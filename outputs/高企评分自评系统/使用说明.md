# 高新技术企业认定评分自评系统 · 使用说明

## 〇、在线地址（手机/电脑随时打开）

**https://hitech-score.app.workbuddy.host/**

手机、平板、电脑浏览器直接打开即可，也可装成桌面图标（见第七节）。

## 一、本地怎么打开

**双击 `index.html`** 即可运行。零依赖、零安装、无需联网、无需后端，数据只留在你自己的浏览器里。

> 建议用 Chrome / Edge 最新版。IE 不支持。

## 二、六步完成自评

| 步骤 | 干什么 | 关键口径 |
|---|---|---|
| ① 企业档案与资格预检 | 填成立日期、人员、财务与研发投入 | **一票否决项 8 条**，任一不满足即不能认定，先解决再打分 |
| ② 知识产权（≤30） | 录入知识产权台账 + 4 个评分子项档位 | Ⅰ/Ⅱ类分开；Ⅱ类仅限使用一次；未授权不计分；加分后本指标不超 30 |
| ③ 科技成果转化（≤30） | 录入近 3 年转化成果清单 | 年平均数 = 总数 ÷ 实际经营年数；同一成果多形式转化只计 1 项 |
| ④ 研发组织管理（≤20） | 4 组各选完备程度档位 | 6 + 6 + 4 + 4；制度类材料补齐即可提档，性价比最高 |
| ⑤ 企业成长性（≤20） | 填近三年净资产与销售收入 | 三态算法：满 3 年两段公式；满 2 年单段降维；刚满 1 年 0 分 |
| ⑥ 结果与诊断 | 看总分、雷达图、明细表与整改建议 | 达标判定一律以**保守总分**为准 |

右侧面板**实时算分**，改任何一个输入即时重算。

## 三、分数怎么看

- **保守总分**：各评分项取政策区间**下界**之和 —— 这是**判定是否达标的唯一依据**（>70，整数口径即 ≥71）。
- **乐观总分**：各评分项取区间**上界**之和 —— 仅作冲刺目标，**不能用于判断是否达标**。
- **实务参考值**：仅"知识产权获得方式"一项提供（自主研发 4 分 / 受让 2 分），因官方该档区间为 1-6 分、下界同为 1，用作准备材料的经验参考，**不进主分**。

## 四、导出与保存

| 功能 | 说明 |
|---|---|
| 导出 PDF（打印） | 点击后在打印对话框选择"另存为 PDF"，A4 排版已优化，含报告抬头与免责声明 |
| 导出 Excel | 生成 5 个工作表：评分明细 / 知识产权台账 / 成果转化台账 / 整改建议 / 资格预检 |
| 保存草稿 | 存到本机浏览器 localStorage（换设备或清缓存会丢，务必配合备份） |
| 备份 JSON / 导入备份 | 导出为文件长期保存，可随时导入恢复 |
| 生成分享链接 | 把填报数据编码进 URL，发给顾问即可复现（注意链接内含数据副本，只发给可信对象） |

## 五、重要提示

1. **本系统不是官方系统**，不代办、不承诺"包过"，测算结果仅供参考，最终以认定机构评审结论为准。
2. 政策依据为《高新技术企业认定管理办法》（国科发火〔2016〕32 号）及《高新技术企业认定管理工作指引》（2016 版）。**网上流传的"组织管理 30 分、成果转化 20 分、净资产 9 + 销售收入 7 + 年平均利润率 4"是已废止的 2008 版口径，本系统不采用。**
3. 各地可能有实施细则差异，本版本仅实现国家版规则包（`policy_version = national-2016`）。
4. 企业财务与知识产权属敏感数据：本系统所有计算均在本地浏览器完成，不上传任何服务器；导出文件请自行妥善保管。

## 六、文件结构

```
index.html                 页面结构
assets/rule-engine.js      评分规则引擎（配置化规则 + 三态成长性算法，可单独用 Node 跑测试）
assets/app.js              交互、渲染、导出、本地存储、规则包更新
assets/styles.css          样式（含 A4 打印样式）
rules/policy.json          规则包（远程更新用，改政策只改这个文件）
manifest.webmanifest       PWA 清单（安装到桌面用）
sw.js                      Service Worker（离线缓存）
icons/                     应用图标（192 / 512 / apple-touch-icon）
使用说明.md                 本文件
```

规则引擎与界面完全解耦：改政策只需改规则包，不需要改界面代码。

## 七、安装到手机 / 电脑桌面（PWA）

| 设备 | 操作 |
|---|---|
| **Android / 电脑（Chrome、Edge）** | 打开在线地址 → 右上角菜单 →「安装应用」/「添加到主屏幕」→ 桌面出现图标，点开全屏运行，**断网也能用** |
| **iPhone / iPad（Safari）** | 用 **Safari** 打开 → 底部「分享」→「添加到主屏幕」（微信内置浏览器不支持安装） |

本系统是 PWA（渐进式 Web 应用）：有 App 的安装体验与离线能力，但**不需要应用商店审核、不需要下载安装包、政策更新即时生效**——这正是政策类工具最合适的形态（政策常变，原生 App 每次改规则都要重新打包 + 等审核）。

## 八、怎么随时更改 / 上传更新

评分规则（档位、上限、边界条件、政策文案、免责声明）全部集中在**规则包**里，与代码分离。三种更新方式：

| 方式 | 适用场景 | 操作 |
|---|---|---|
| **① 远端更新（推荐）** | 政策调整，希望所有用户立刻用上新规则 | 把新的 `rules/policy.json` 放到服务器同一目录（重新发布一次），用户点页面第 ⑦ 区「检查远端更新」即可生效；**无需重新安装、无需清缓存** |
| **② 手动导入** | 单机使用 / 临时改规则 | 第 ⑦ 区「导入规则包」选择改好的 policy.json，立即生效并保存在本机 |
| **③ 改代码基线** | 需要长期固化 | 编辑 `assets/rule-engine.js` 顶部 `POLICY` 配置对象 |

规则包怎么改：先点「导出当前规则包」得到 policy.json，用文本编辑器改其中的数值（如把成果转化 A 档下限 `[25,30]` 改成新口径），保存后导入或上传即可。**切换规则包不会影响已填写的填报数据。**

> 规则包关键字段：`policy_version`（版本号）、`pack_updated_at`（更新日期，用于判断新旧）、
> `ip.items[].bands`（知识产权各子项档位）、`transform.bands`（成果转化分档）、
> `rdmgmt.ratio_bands`（组织管理六档比例）、`growth.bands`（成长性分档）、`precheck`（一票否决项）。

## 九、关于微信小程序

当前交付的是**网页 + PWA**，不是小程序。小程序是完全不同的代码体系（WXML/WXSS + app.json，不是 HTML/DOM），无法由本项目直接转换。

如果确实需要小程序，建议路径：

1. **先用网页版跑通**——本次交付的网页就是功能与口径的事实标准；
2. 需要时新建小程序项目（用「代码开发」选小程序类型），**复用本项目的规则包 `rules/policy.json` 与 `rule-engine.js` 的算法逻辑**（这两部分与界面无关，可直接移植）；
3. 小程序需单独注册主体、备案、提交微信审核；建议只做轻量版（资格预检 + 粗测），完整测算与报告导出仍引回网页——这与我们此前"不做全功能小程序"的判断一致：长表单在小程序体验差、PDF 导出割裂、审核周期与政策热修冲突。
