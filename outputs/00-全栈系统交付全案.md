## 1. 项目三要素

| 要素 | 结论 |
|------|------|
| **做什么系统** | 高新技术企业认定创新能力评分在线自评测算网站（PC Web 响应式 + Web 管理后台） |
| **面向谁** | ①拟申报/复审高企的科技型中小企业的项目申报负责人、研发与财务负责人（主用户）；②科技服务/知识产权代理机构顾问（专业用户，V1.1）；③园区与孵化器运营方（V2.0 渠道） |
| **核心目标** | 让用户按官方口径 3 分钟完成四项指标自评，得到**保守总分 + 达标判定 + 差距诊断 + 整改建议 + 可导出报告**，降低申报摸底成本 |

**北极星指标**：WCSO（周有效自评完成去重主体数），V1.0 目标：上线第 4 周单周 ≥120（详见 §6 裁决 G1）。

## 2. 执行摘要（一页看懂）

| 维度 | 结论 |
|------|------|
| **平台形态** | **PC Web 响应式单端 + Web 管理后台**；明确不做 App / 微信小程序 / 鸿蒙 / 桌面端（低频长表单场景，且政策规则需热修、与商店审核周期冲突）。小程序仅保留 V2.0 条件触发（移动端访问 >40% 且有微信内传播需求） |
| **MVP 规模** | V1.0 = **15 个功能点**，**62~72 人日**，**6~9 周** |
| **技术栈** | Next.js 14.2（App Router）+ React 18.3 + TS 5.4 strict + antd 5.20 + ECharts 5.5 + Zustand + zod；Node 20.11 + Next Route Handlers（模块化单体）+ Prisma 5.16 + MySQL 8.0.36；Redis 7.2.5（可降级进程内）；腾讯云 COS 私有桶；PDF＝Playwright headless Chromium + 思源黑体子集；Excel＝ExcelJS；单机 2C4G + Docker Compose + Nginx + certbot；CI＝GitHub Actions；pino + Sentry + Uptime Kuma |
| **系统核心** | 规则引擎 `@hitech/rule-engine`（纯 TS 包），浏览器端实时算分 ≤800ms，服务端同包复算，**双端一致性 100% 是硬门禁**；规则配置化 + `policy_version` 版本管理，历史评分可复算 |
| **关键路径** | **ICP 备案 1~3 周**（第 1 天即启动），备案未通过严禁对外正式发布 |
| **成本** | 淡季 ≈230~275 元/月，申报季 ≈350~585 元/月（落在 200~600 元/月预算带） |
| **质量门禁** | P0 缺陷 = 0（PR / 预发 / 发布三处均卡）、P1 ≤3、规则引擎单测覆盖率 ≥95%、双端一致性 100%、E2E 主流程 100%、算分 P95 ≤800ms、安全扫描无高危 |
| **稳定性** | SLO 月度可用性 ≥99.5%；RPO ≤15min（申报季 ≤5min）、RTO ≤60min（申报季 ≤45min）、整机重建 RTO ≤4h |
| **最大风险** | ①规则包错误导致分数系统性算错（误导申报决策）→ 发布前影子复算 + 发布后 30 分钟分布哨兵 + 自动回滚三道闸；②备案延期；③PDF 中文字体未嵌入 |

## 4. 政策评分口径总表（全团队唯一事实基线，已联网核验）

**判定规则**：四项指标满分 100 分，各级指标按整数打分，**综合得分 > 70 分（不含 70）为符合认定要求**，整数口径即 **≥71**。系统同时给出保守总分（各子项区间下界之和，作为达标判定依据）与乐观总分（上界之和，仅作冲刺目标展示）。

### 4.1 知识产权（≤30，加分后本指标总分不超过 30）

| 评分子项 | 上限 | A | B | C | D | E |
|---|---|---|---|---|---|---|
| 技术的先进程度 | ≤8 | 高 7-8 | 较高 5-6 | 一般 3-4 | 较低 1-2 | 无 0 |
| 对主要产品(服务)核心支持作用 | ≤8 | 强 7-8 | 较强 5-6 | 一般 3-4 | 较弱 1-2 | 无 0 |
| 知识产权数量 | ≤8 | Ⅰ类 ≥1项 7-8 | Ⅱ类 ≥5项 5-6 | Ⅱ类 3~4项 3-4 | Ⅱ类 1~2项 1-2 | 0项 0 |
| 知识产权获得方式 | ≤6 | 有自主研发 1-6 | 仅有受让/受赠/并购等 1-3 | — | — | 无 0 |
| 参与编制国标/行标/检测方法/技术规范（加分项） | ≤2 | 是 1-2 | 否 0 | — | — | — |

- Ⅰ类＝发明专利（含国防专利）、植物新品种、国家级农作物品种、国家新药、国家一级中药保护品种、集成电路布图设计专有权；Ⅱ类＝实用新型、外观设计、软件著作权（不含商标）。
- **Ⅱ类仅限使用一次**，复审/重新认定须剔除已用项；专利以授权证书（或授权通知书 + 缴费收据）为准；多个权属人时只能由一个权属人使用。
- "获得方式"报告层另展示**实务参考值**（自主研发 A=4、受让 B=2），仅作展示，不进主分。

### 4.2 科技成果转化能力（≤30）

近 3 年科技成果转化**年平均数**（N＝实际经营年数）：

| 档位 | A | B | C | D | E | F |
|---|---|---|---|---|---|---|
| 年均项数 | ≥5 项 | ≥4 项 | ≥3 项 | ≥2 项 | ≥1 项 | 0 项 |
| 分值 | [25,30] | [19,24] | [13,18] | [7,12] | [1,6] | 0 |

同一科技成果在国内外转化，或转化为多个产品/服务/工艺/样品/样机的，**只计一项**。

### 4.3 研究开发组织管理水平（≤20）

| 序 | 评价内容 | 上限 |
|---|---|---|
| ① | 制定研发组织管理制度 + 建立研发投入核算体系 + 编制研发费用辅助账 | ≤6 |
| ② | 设立内部研发机构并具备科研条件 + 开展产学研合作 | ≤6 |
| ③ | 建立成果转化组织实施与激励奖励制度 + 建立开放式创新创业平台 | ≤4 |
| ④ | 建立科技人员培养进修 / 职工技能培训 / 优秀人才引进 / 人才绩效评价奖励制度 | ≤4 |

### 4.4 企业成长性（≤20）

净资产增长率 ≤10 ＋ 销售收入增长率 ≤10，六档赋分：≥35% [9,10]｜≥25% [7,8]｜≥15% [5,6]｜≥5% [3,4]｜>0 [1,2]｜≤0 0。

**三态算法（`biz_years ∈ {1,2,3}`，禁止布尔参数）**：

| 情形 | 公式 / 结果 |
|---|---|
| biz_years ≥3 | `g = 1/2 × (v2/v1 + v3/v2) − 1` |
| biz_years ≥3 且 v1 = 0 | `g = v3/v2 − 1`（政策明示按后两年计算） |
| biz_years ≥3 且 v2 = 0（含 v1=v2=0） | `g = 0` |
| biz_years = 2 | `g = v2/v1 − 1`（**单段降维，不得套用 v3/v2**）；v1 = 0 → g = 0 并标记"数据不足" |
| biz_years = 1 | 成长性整体 0 分 |
| 任一增长率 < 0 | 按 0 分 |

净资产与销售收入两个指标**各自独立**走上述分支，互不牵连。

### 4.5 前置资格预检（一票否决项，必须做成独立模块）

| # | 条件 | 阈值 |
|---|---|---|
| 1 | 注册成立 | ≥1 年（365 个日历天数以上） |
| 2 | 核心自主知识产权 | 无知识产权 → 不能认定 |
| 3 | 技术领域 | 主要产品(服务)属《国家重点支持的高新技术领域》 |
| 4 | 科技人员占比 | ≥10%（当年职工总数口径，累计工作 ≥183 天） |
| 5 | 研发费用占比 | 近三年度合计 ÷ 同期销售收入：最近一年销售收入 <5000 万(含)→5%；5000 万~2 亿(含)→4%；>2 亿→3% |
| 6 | 境内研发费用占比 | ≥60% |
| 7 | 高新技术产品(服务)收入占比 | ≥60%（申报前一年口径） |
| 8 | 合规记录 | 申请前一年未发生重大安全 / 重大质量事故或严重环境违法行为 |

## 5. 五阶段结论精要

### Phase 1 · 立项与定义

| 成员 | 核心结论 |
|---|---|
| 选品洞察师 | PC Web 单端即完整承接（办公桌 + 低频 + 长表单 + 需导出 + 无系统能力依赖）；不做 App/小程序/鸿蒙/桌面；MVP 12 功能点起点、62~72 人日、6~9 周；合规红线三条（不承诺包过、敏感数据保护、政策引用标注文号+条款+版本日期）；生成式 AI 建议不做（规避《生成式人工智能服务管理暂行办法》备案义务），改用规则化建议模板库 |
| 产品主理人 | 功能 34 项（P0=16→收敛 15、P1=11、P2=7）；V1.0=F-02~F-16，V1.1=F-17~27，V2.0=F-28~34；采用"区间评分 + 保守/乐观双轨"；E1~E13 异常分支逐条定义出口；北极星 WCSO + 22 个埋点事件 |
| 全栈研发师 | 模块化单体 + 规则引擎双端复用；规则配置化（YAML/DB 双写 + `policy_version` + `region_code` 预留）；10 类核心表；RESTful API 分层；PDF 走 Playwright 打印路由（中文 A4 保真）；单机 Docker Compose 部署 |

### Phase 2 · 质量保障（质量测试官）

- 四层测试策略 + 卡点位置；规则引擎专项：成长性 16 组边界用例（8 场景 × 2 指标）、知识产权档位边界与Ⅱ类去重、成果转化除数与"只计一项"、资格预检七项否决、双端一致性 golden case、规则包版本复算不变性。
- 门禁 G-01~G-20：**P0 = 0**（三处均卡）、P1 ≤3、覆盖率 ≥95%、双端一致性 100%、E2E 100%、算分 P95 ≤800ms、安全扫描无高危、PDF 字形覆盖率 100% 无 tofu。

### Phase 3 · 上线发布（上线发布师）

- 四套环境（dev / preview / staging / prod）；GitHub Actions 流水线含规则引擎单测 + 双端一致性快照 + 镜像构建 + staging E2E + 人工确认 + prod + 发布后冒烟。
- **ICP 备案时间线**：D1 启动 → D2~D5 云厂商初审 → D5~D20 管局审核（并行开发）→ ~W3 备案号下发 → ~W6 SSL 签发与正式发布窗口（避开申报截止前 7 天）。**备案未通过严禁对外发布**。
- 分级回滚：应用（切镜像 tag）、规则包（版本回退 + 历史记录影响评估）、数据库（expand→migrate→contract，禁止不可逆变更）、短链与 COS 产物兼容。

### Phase 4 · 运维保障（运维守护师）

- 单机 2C4G 单故障域：用"异地加密备份 + 三道规则闸 + 三层监控 + 500 元/月硬预算"对冲。
- 告警阈值分层（基础设施 / 应用 / 业务），含业务层哨兵：**平均总分分布异常**用于发现规则包算错分。
- 应急预案覆盖：数据库故障、Redis 不可用、磁盘写满、Chromium OOM / PDF 队列积压、**规则包错误导致系统性算错分（最高危）**、短链异常、COS 不可用、证书过期、暴刷、**数据泄露（72 小时合规时钟，按《个人信息保护法》第 57 条处理）**。
- 备份：每日全备 + binlog（常态 15min / 申报季 5min 同步 COS）；**RPO ≤15min、RTO ≤60min**（申报季 ≤5min / ≤45min）；整机重建 RTO ≤4h；每月恢复校验 + 每季度全流程演练。

### Phase 5 · 增长运营（增长运营师）

- 获客以 **SEO 内容矩阵**为主（政策词条页 + 长尾词 + FAQ Schema + 政策变动 48h 内更新），辅以知乎/公众号/财税社群/园区与代理机构合作。
- 留存：复评提醒、政策更新订阅、"我的分数变化"回访、短链回访二次激活、代理机构多客户留存。
- 指标基线：漏斗各环节转化率、导出率、分享率、留资转化率、SEO 收录与排名，均给出目标值与预警线；运营日历按申报季（4~8 月）与淡季分节奏。

| TB-07 | 导出脱敏开关默认值 | **本地导出默认不脱敏**（报告给用户自己/顾问用，脱敏即不可用）；**短链分享页默认脱敏**（隐藏企业名称与财务金额，仅显示分数与档位）；后台导出强制脱敏；分享场景 UI 提供开关且默认开 |
