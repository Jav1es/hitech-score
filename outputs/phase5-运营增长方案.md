**折中方案（建议采纳，双轨并行 4 周后择一）**：

| 口径 | 定义 | 用途 |
|------|------|------|
| **WCSO-T（过渡口径，V1.0 主考核）** | 统计周期内完成四项打分且生成 ≥1 份报告的去重**主体数**；主体 = 已登录取 `user_id`，游客取服务端签发的 `guest_token_hash`（与技研 `events.guest_token_hash` 同源），生成短链快照时归并为同一主体 | V1.0 上线 12 周内唯一对外汇报口径 |

## 1. 增长目标与模型

### 1.1 北极星指标：WCSO（周有效自评完成企业数）

**口径（WCSO-T）**：统计周期（自然周，周一 00:00 ~ 周日 23:59）内，完成四项指标全部填写（`scoring_records.status=completed`）**且**生成 ≥1 份诊断报告的去重主体数。

**PRD 目标**：上线第 4 周单周 ≥120；上线 12 周累计 ≥800。

### 1.2 WCSO 分解树（六层漏斗，每层有责任人与杠杆）

```
WCSO（周有效自评完成主体数）
└─ × 报告生成率 R5                    ← 结果页钩子 / 报告价值感（PRD ≥60%）
   └─ 四项打分完成数
      └─ × 四项打分完成率 R4          ← 表单体验 / 引导向导 F-23（PRD ≥55%）
         └─ 预检通过数
            └─ × 预检通过率 R3        ← 观测值，政策刚性，不做目标
               └─ 建档完成数
                  └─ × 建档完成率 R2  ← 字段精简 / 免登录（PRD ≥70%）
                     └─ CTA 点击数
                        └─ × 首屏 CTA 点击率 R1 ← 落地页信息架构 / 卖点（假设 35%）
                           └─ 访问 UV
                              ├─ 自然搜索（SEO 内容页）  目标占比 ≥50%
                              ├─ 直接访问/品牌词
                              ├─ 内容平台（知乎/公众号/视频号）
                              ├─ 社群/私域
                              ├─ 园区·孵化器
                              └─ 代理机构分发（V1.1 起）
```

**WCSO 反推公式**（运营侧周会必算）：

```python3
# wsco_backsolve.py —— 由目标 WCSO 反推各环节所需流量
# 用法: python3 wsco_backsolve.py --target 120 --season 1.0
import argparse

# 【假设基线】上线首月各环节转化率（第 2 周用真实数据替换）
BASE = {
    "r1_cta":        0.35,  # landing_view -> cta_click
    "r2_org":        0.70,  # cta_click   -> org_create        (PRD ≥70%)
    "r3_precheck":   0.60,  # org_create  -> precheck pass     (观测值)
    "r4_score":      0.55,  # pass        -> 4 模块 complete   (PRD ≥55%)
    "r5_report":     0.60,  # complete    -> report_generate   (PRD ≥60%)
    # 注：export(45%) / 留资(8%) 不计入 WCSO，是 WCSO 之后的"价值放大"层
}

def required_uv(target: int, rates=BASE) -> float:
    e2e = 1.0
    for v in rates.values():
        e2e *= v
    return target / e2e

def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--target", type=int, default=120)
    ap.add_argument("--season", type=float, default=1.0,
                    help="季节系数: 旺季1.5 / 平季1.0 / 淡季0.5")
    a = ap.parse_args()
    e2e = 1.0
    for k, v in BASE.items():
        e2e *= v
    uv = a.target / e2e / a.season
    print(f"端到端转化率(访问->出报告) = {e2e:.4%}")
    print(f"季节系数 = {a.season}")
    print(f"达成 WCSO={a.target} 需要周访问 UV ≈ {uv:,.0f}")
    print("分环节所需量级：")
    n = uv
    for k, v in BASE.items():
        n *= v
        print(f"  {k:<14} ×{v:.0%} -> 累计 {n:,.0f}")

if __name__ == "__main__":
    main()
```

**首月测算结果（假设基线）**：端到端转化率 ≈ **4.85%**，即每 100 个访问约产出 4.85 份报告。
→ 达成 WCSO=120（平季）需要 **周访问 UV ≈ 2,474**；旺季（系数 1.5）需 ≈1,650；淡季（系数 0.5）需 ≈4,950。

## 2. 冷启动获客（V1.0 零预算打法）

> 纪律：选型报告 §3.6 判定"搜索引擎是几乎唯一的主流量来源"。因此 **V1.0 只主攻 2 个渠道（SEO 内容站 + 知乎/公众号），其余渠道只做种子与试点，不铺开**。

### 2.1 种子用户（前 200 人，W1~W3）

**画像（具体而非泛化）**：年营收 500 万~2 亿、员工 20~300 人的制造业/软件/新材料企业里，**第一次或第二次申报高企、公司没有专职政策研究岗**的项目申报专员或行政/总经办经办人；以及服务 5~30 家客户的**知识产权/科技服务代理机构项目经理**。

| 动作 | 具体做法 | 频次 | 成本 | 预期量级 |
|------|----------|------|------|----------|
| 竞品评论区截流 | 在竞品（选型报告 §6.1 所列 6 类）的文章/工具页评论区、以及"高企评分表 Excel 下载"类帖下，以**回答者身份**给出正确口径（成长性公式、Ⅱ类只能用一次），签名挂站点链接 | 每周 5 条 | ¥0 | 30~60 UV/周 |

### 2.2 SEO 内容矩阵（P0 主攻渠道）

#### 2.2.1 关键词分层与选词依据

**选词四原则**（写在内容选题会入口）：
1. **意图明确度**：问答型/计算型词（"怎么算""怎么算分""几分"）优先，泛词（"高新技术企业"）不碰；
2. **工具可承接性**：该词对应的问题必须能在站内被"直接算/直接判"承接，否则只做品牌曝光不投入；
3. **竞品空白**：选型报告 §6.2 指出的 6 条竞品短板（资格预检、区间双档、成长性公式、政策溯源、材料映射、SEO 弱）是选词富矿；

**内链巡检脚本（python3，每周跑一次）**：

```python3
# internal_link_audit.py —— 巡检内链健康度（孤岛页 / 到工具跳数）
# 用法: python3 internal_link_audit.py --sitemap sitemap.xml
import re, sys, argparse, xml.etree.ElementTree as ET
from collections import deque, defaultdict

def load(urls_file):
    """urls_file: 每行一条 'url<TAB>out:url1,url2' 由构建期生成"""
    g = defaultdict(list)
    with open(urls_file, encoding="utf-8") as f:
        for line in f:
            if not line.strip():
                continue
            u, _, outs = line.partition("\t")
            g[u.strip()] = [x.strip() for x in outs.replace("out:", "").split(",") if x.strip()]
    return g

def bfs_hops(g, start="/assess"):
    """反向：从工具页出发做反向 BFS，得到每个页面到工具的最短跳数"""
    rev = defaultdict(list)
    for u, outs in g.items():
        for v in outs:
            rev[v].append(u)
    dist = {start: 0}
    q = deque([start])
    while q:
        cur = q.popleft()
        for pre in rev.get(cur, []):
            if pre not in dist:
                dist[pre] = dist[cur] + 1
                q.append(pre)
    return dist

def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--links", required=True)
    ap.add_argument("--max-hop", type=int, default=3)
    a = ap.parse_args()
    g = load(a.links)
    dist = bfs_hops(g)
    orphan = [u for u, outs in g.items() if not outs]
    far = [(u, d) for u, d in dist.items() if d > a.max_hop]
    unreachable = [u for u in g if u not in dist]
    print(f"页面总数            : {len(g)}")
    print(f"孤岛页（无出链）    : {len(orphan)} -> {orphan[:10]}")
    print(f"到工具 >{a.max_hop} 跳   : {len(far)} -> {far[:10]}")
    print(f"不可达工具页        : {len(unreachable)} -> {unreachable[:10]}")
    if orphan or unreachable:
        sys.exit(1)  # CI 红：禁止发布

if __name__ == "__main__":
    main()
```

**JSON-LD 生成脚本（python3，构建期调用）**：

```python3
# build_schema.py —— 生成词条页 FAQPage + BreadcrumbList + Article 的 JSON-LD
# 用法: python3 build_schema.py page.json > out/schema.jsonld
import json, argparse, datetime

SITE = "https://hitech.example.com"
DISCLAIMER = "仅供参考，最终以认定机构评审为准"

def faq_page(faqs):
    return {
        "@context": "https://schema.org",
        "@type": "FAQPage",
        "mainEntity": [
            {
                "@type": "Question",
                "name": q["q"],
                "acceptedAnswer": {
                    "@type": "Answer",
                    # 合规硬要求：每个答案尾部拼接免责表述，禁止省略
                    "text": q["a"].rstrip() + f"（{DISCLAIMER}）",
                },
            }
            for q in faqs
        ],
    }

def breadcrumb(trail):
    return {
        "@context": "https://schema.org",
        "@type": "BreadcrumbList",
        "itemListElement": [
            {"@type": "ListItem", "position": i + 1, "name": n, "item": SITE + u}
            for i, (n, u) in enumerate(trail)
        ],
    }

def article(title, published, modified, rule_version):
    return {
        "@context": "https://schema.org",
        "@type": "TechArticle",
        "headline": title,
        "datePublished": published,
        "dateModified": modified,
        "author": {"@type": "Organization", "name": "本站政策内容组"},
        "publisher": {"@type": "Organization", "name": "本站"},
        # 规则版本外显，便于用户核对时效性
        "about": f"高新技术企业认定创新能力评价口径，规则版本 {rule_version}",
    }

def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("page_json")
    a = ap.parse_args()
    p = json.load(open(a.page_json, encoding="utf-8"))
    out = [
        faq_page(p["faqs"]),
        breadcrumb(p["trail"]),
        article(p["title"], p["published"],
                p.get("modified", p["published"]), p["rule_version"]),
    ]
    print(json.dumps(out, ensure_ascii=False, indent=2))

if __name__ == "__main__":
    main()
```

> **合规注意**：Schema 中**不得**出现企业名称、财务数据、联系方式等任何用户侧字段；词条页 Schema 只描述公共政策内容。

### 3.3 "3 分钟出分"承诺的话术与真实性边界

**这是最容易踩合规与信任红线的点，必须严格限定。**

| 项 | 规定 |
|----|------|
| **可用表述** | "最快 3 分钟完成资格预检"（仅指预检 8 项）；"熟练用户约 10 分钟完成完整自评"（对齐 PRD §2.1 与选型报告 §1.1 的 10 分钟口径） |
| **禁用表述** | "3 分钟出分""3 分钟拿到报告""3 分钟知道能不能过" —— 因为完整流程需录入知识产权台账、成果转化清单、三年财务数据，绝大多数用户无法在 3 分钟内完成 |
| **真实性依据** | 用埋点 `report_generate - org_create` 的时间差中位数作为对外表述依据；**P50 ≤10 分钟才可用"约 10 分钟"**，否则改为"多数用户在 15 分钟内完成" |
| **落地页写法** | 主标题用"10 分钟"（与 PRD 一致），并在流程图解处标注"资格预检最快 3 分钟，完整自评约 10 分钟（视材料齐备程度）" |
| **A/B 例外** | 只有在埋点证实 P50 完成时长 ≤3 分钟时，才允许在实验中测试"3 分钟"表述；未证实前一律禁用 |

| **E7** | 词条页工具卡位置：首屏顶部 vs 文中嵌入 | 如果迷你计算器放在结论下方首屏内（顶部），则词条页 → /assess 的跳转率提升 ≥30%，因为搜索用户要的是"算"不是"读" | 词条页 → 工具跳转率 | 页面停留时长（不得 <40s，防"秒跳"伤 SEO）、词条页跳出率 | W7~W8 | 1,331 | 跳转率 +≥30% 且停留 ≥40s → 全量 |
| **E8** | 报告页留资钩子：单个钩子 vs 双钩子（云端保存 + 政策订阅） | 如果报告页同时给"保存到云端"与"订阅政策更新"两个独立可跳过钩子，则留资率提升 ≥5pp，因为给了不同诉求的退出选择 | 留资转化率 | 报告页跳出率、退订率 | W8~W9 | 1,331 | 留资率 +≥5pp → 全量 |

**最小样本量计算（python3，每个实验开跑前必算）**：

```python3
# ab_sample_size.py —— 两比例检验最小样本量（双尾 alpha=0.05, power=0.80）
# 用法: python3 ab_sample_size.py --baseline 0.35 --mde 0.15
import argparse, math

Z_A = 1.959963985  # alpha=0.05 双尾
Z_B = 0.841621234  # power=0.80

def sample_size(p1: float, mde_rel: float) -> int:
    p2 = p1 * (1 + mde_rel)
    if p2 >= 1.0:
        raise ValueError("p2 >= 1，请降低 MDE")
    num = (Z_A + Z_B) ** 2 * (p1 * (1 - p1) + p2 * (1 - p2))
    den = (p2 - p1) ** 2
    return math.ceil(num / den)

def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--baseline", type=float, default=0.35, help="当前基线转化率")
    ap.add_argument("--mde", type=float, default=0.15, help="相对提升幅度，如 0.15 = +15%")
    ap.add_argument("--daily-traffic", type=int, default=350,
                    help="该环节日均样本量（用于估算所需天数）")
    a = ap.parse_args()
    n = sample_size(a.baseline, a.mde)
    days = math.ceil(n * 2 / a.daily_traffic)  # 两臂合计
    print(f"基线 p1 = {a.baseline:.4f}, 相对 MDE = +{a.mde:.0%} -> p2 = {a.baseline*(1+a.mde):.4f}")
    print(f"每臂最小样本量 n = {n:,}")
    print(f"两臂合计       = {n*2:,}")
    print(f"按日均 {a.daily_traffic} 样本估算，需 {days} 天（建议至少跑满 2 个完整周以覆盖周内效应）")

if __name__ == "__main__":
    main()
```

> **小流量兜底**：V1.0 早期日样本不足（如 W1 日均 UV 仅 60），单个实验跑不满最小样本量时的处理——①延长周期至累计达标（最长 4 周）；②将 MDE 放宽到 +25%（需明确标注"结论置信度较低"）；③**禁止**在未达样本量时下"显著"结论。所有实验结论须带置信区间入台账。

**实验台账字段**（所有实验含失败必录）：实验 ID / 假设 / 变量 / 分流方式 / 主指标 / 护栏指标 / 样本量 / 周期 / 结果（含置信区间）/ 决策（全量/关闭/回滚）/ 沉淀认知。

### 4.5 六个留存机制的具体设计

#### 4.5.1 复评提醒（申报季前触达 —— 最高优先级，对应 W2）

- **触发**：地区规则包（R-04）配置的批次时间前 **60 天 / 30 天 / 7 天**；未配置地区的用户按"往年批次月份"推断，并在文案中注明"以当地认定机构公告为准"。
- **分层**：
  - 上次达标（≥71）：文案重心 = "维持与复核，别在材料上翻车"；
  - 上次边缘（66~70.9）：重心 = "差 X 分，这 30 天还能补的 3 件事"；
  - 上次不达标（<66）：重心 = "今年补齐路径 + 明年规划"。
- **话术公式**（身份认同 + 具体钩子 + 低门槛行动）：
  > "你上次自评 **68.5 分**（保守档），距离 71 分线差 **2.5 分**。本地区申报批次预计 **X 月**启动，还有 **30 天**。点此用上次的方案一键复评，系统会只让你改变化过的项。"
- **落地页**：**直达"一键复评"页（预填上次数据）**，不落首页（参考文件 §5.2 召回后承接要求）。
- **指标**：复评提醒打开率、复评完成率（复评后 `report_generate` 占比）、7 日内二次流失率。

#### 4.5.2 政策更新订阅（对应 W1）

- **订阅入口**：结果页 H3 钩子（可跳过）、报告页、词条页侧边栏；**订阅只需邮箱，不强制手机号**（最小必要）。
- **推送内容模板**（三段式，禁止 AI 生成）：
  1. 变了什么（文号 + 条款 + 前后对照）；
  2. 影响哪些评分项（列出 `indicator_code`）；
  3. 对你分数的影响（"你的方案 IP 项可能从 24 变 26，总分区间 66~72 → 68~74"）+ "点此一键复评"。
- **SLA**：与 §2.2.4 同源，T+48h 内发出。
- **指标**：订阅转化率（目标 ≥8%）、订阅打开率（目标 ≥35%）、退订率（预警线 >5%）、退订后 30 日留存。

#### 4.5.3 "我的分数变化"回访（对应 W3）

- **触发**：用户上次自评未达标（保守总分 <71）且距上次活跃 ≥60 天，**且处于申报季或规划季**（淡季不触发，避免无效触达）。
- **内容**：并排展示"上次 vs 现在"（需用户复评后才可生成；未复评时退化为"你上次差 X 分，建议补的 3 件事进展如何？"）。
- **激励**：无现金激励（B 端场景）；给的是"补齐进度清单 + 材料模板"（低成本高价值）。
- **指标**：回访打开率、复评转化率。

#### 4.5.4 企业年度自评习惯培养（对应 W6）

- **机制**：每年 1 月向去年有过自评记录的用户推"年度自评提醒"，**预填去年数据**（财务三年窗口滚动，需用户确认更新），把"从零填一次"变成"改几个数字"。
- **价值主张**："去年你 68.5 分，今年净资产与收入变了，点此 3 分钟更新两个数，看今年到几分。"
- **成本**：依赖 V1.1 账号体系 + V2.0 F-31 政策更新订阅；V1.0 只能靠短链（30 天）覆盖，因此**年度自评在 V1.0 不成立，V1.1 起才有意义**（明确标注，不吹牛）。

| 手段 | 内容 | 指标 |
|------|------|------|

#### 4.5.6 短链回访与二次激活（V1.0 唯一可用的触达载体）

- **短链机制**：PRD 附录 B.1 —— 服务端保存快照，**30 天有效，链接即凭证，不暴露企业敏感信息**。
- **回访设计**：
  - 第 25 天：短链页顶部提示"链接 5 天后过期，绑定邮箱可永久保存"（事务性，1 次）；

### 4.6 流失定义与分层召回

#### 4.6.1 流失定义（按业务节奏，非按日活）

| 概念 | 定义（写进数据口径） | 依据 |

| **活跃** | 30 天内有 ≥1 次 `scoring_open` 或 `report_generate` | 低频工具 |

#### 4.6.2 三层召回策略（渠道 / 话术 / 激励 / 成本）

| 层 | 定义 | 召回重点 | 渠道优先级 | 话术示例 | 激励 | 召回成本 | 目标召回率 |
|----|------|----------|------------|----------|------|----------|------------|

| **L3 沉睡用户** | 180 天未活跃 | **新功能卖点 + 强钩子** | 邮件 → 短信（**仅**重大政策变更时） | "过去 6 个月我们上线了：方案对比、批量导入、机构工作台。政策口径也更新到 v2026.10。你的旧方案可以一键升级查看新分数" | 新功能 + 政策版本升级 | 邮件 ≈¥0.01；短信 ≈¥0.05/条（**仅重大变更，每月 ≤1**） | ≥8% |

**召回成本上限**：单用户年度召回成本 **≤¥0.3**（邮件为主，短信严格限量）；召回成本必须 < 用户 LTV。V1.0 无营收，LTV 用"单个有效自评主体的战略价值"替代估算 —— 按 §9.2 机构版 ¥299~999/席/月反推，**单企业线索价值保守估计 ≥¥50**，因此 ¥0.3 的召回成本天花板是安全的（约 0.6%）。

**召回落地页纪律**：召回链接**直达钩子内容**（继续填写页 / 补齐清单页 / 一键复评页），**不落首页**（参考文件 §5.2）。

**召回后监控**：召回用户 **7 日内二次流失率**纳入周报（目标 ≤60%）；二次流失率高说明钩子与内容不匹配，需换钩子而非加大激励。

**召回实验**：A/B 激励力度（无激励 / 资料包 / 资料包 + 个性化清单），按 §3.5 的样本量方法判定；**禁止用补贴换虚假活跃**（参考文件 §十 反模式 1）。

### 5.6 基线替换流程（W2 执行）

```python3
# baseline_replace.py —— 第 2 周用真实数据替换【假设基线】，输出正式基线表
# 用法: python3 baseline_replace.py --week 2 --events events_week2.jsonl
import json, argparse
from collections import Counter

FUNNEL = ["landing_view", "cta_click", "org_create",
          "precheck_submit", "score_module_complete", "report_generate"]

def load(path):
    with open(path, encoding="utf-8") as f:
        for line in f:
            if line.strip():
                yield json.loads(line)

def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--week", type=int, required=True)
    ap.add_argument("--events", required=True)
    a = ap.parse_args()

    # 按主体去重（游客用 guest_token_hash，登录用 user_id）
    step_users = {e: set() for e in FUNNEL}
    precheck_pass = set()
    for e in load(a.events):
        uid = e.get("user_id") or e.get("guest_token_hash")
        if not uid:
            continue
        name = e["event_name"]
        if name in step_users:
            step_users[name].add(uid)
        if name == "precheck_submit" and e.get("props", {}).get("pass"):
            precheck_pass.add(uid)

    print(f"=== W{a.week} 真实基线（替换【假设基线】）===")
    prev = None
    for i, s in enumerate(FUNNEL):
        n = len(step_users[s])
        if prev is not None and prev > 0:
            print(f"{s:<24} 主体数={n:>6}  环节转化率={n/prev:>7.2%}")
        else:
            print(f"{s:<24} 主体数={n:>6}")
        prev = n
    print(f"预检通过主体数           = {len(precheck_pass)}")
    print(f"端到端(访问->出报告)     = {len(step_users['report_generate'])/max(len(step_users['landing_view']),1):.4%}")
    print("WCSO(周去重出报告主体数) =", len(step_users["report_generate"]))
    print("\n>> 将本表写入 §5.1 的'正式基线'列，并重算 §1.3 的所需 UV。")

if __name__ == "__main__":
    main()
```

### 6.7 A/B 实验统计口径

| 项 | 规定 |
|----|------|
| 分流单位 | `guest_token_hash`（游客）/ `user_id`（登录），哈希取模 50/50，**跨会话稳定** |
| 显著性 | 双尾 α=0.05，power=0.80；用两比例 z 检验，**必须报告置信区间** |
| 最小样本量 | 见 §3.5 脚本；未达样本量不得下"显著"结论 |
| 实验周期 | 最短 2 个完整周（覆盖周内效应）；最长 4 周，超时未达标则关闭并记录"样本不足" |
| 单变量 | 一次只改一个变量；禁止"改版"式多变量混发 |
| 护栏指标 | 每个实验必设；护栏恶化即回滚（如 E4 的四项打分完成率降 >3pp） |
| 提前停止 | **禁止**中途偷看就停止（peeking problem）；如需序贯检验，改用 O'Brien-Fleming 边界 |
| 台账 | 全部实验（含失败）入台账，字段见 §3.5 |

```python3
# ab_evaluate.py —— 实验结束时的两比例 z 检验 + 置信区间
# 用法: python3 ab_evaluate.py --n1 1331 --c1 466 --n2 1331 --c2 536
import argparse, math

def z_test(n1, c1, n2, c2):
    p1, p2 = c1 / n1, c2 / n2
    p = (c1 + c2) / (n1 + n2)
    se = math.sqrt(p * (1 - p) * (1 / n1 + 1 / n2))
    z = (p2 - p1) / se
    # 双尾 p 值（正态近似）
    pval = 2 * (1 - 0.5 * (1 + math.erf(abs(z) / math.sqrt(2))))
    se_ci = math.sqrt(p1 * (1 - p1) / n1 + p2 * (1 - p2) / n2)
    diff = p2 - p1
    return p1, p2, diff, z, pval, (diff - 1.96 * se_ci, diff + 1.96 * se_ci)

def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--n1", type=int, required=True, help="对照组样本量")
    ap.add_argument("--c1", type=int, required=True, help="对照组转化数")
    ap.add_argument("--n2", type=int, required=True, help="实验组样本量")
    ap.add_argument("--c2", type=int, required=True, help="实验组转化数")
    a = ap.parse_args()
    p1, p2, diff, z, pval, (lo, hi) = z_test(a.n1, a.c1, a.n2, a.c2)
    print(f"对照组 p1 = {p1:.4%}  ({a.c1}/{a.n1})")
    print(f"实验组 p2 = {p2:.4%}  ({a.c2}/{a.n2})")
    print(f"绝对提升   = {diff:+.4%}   相对提升 = {diff/p1:+.2%}")
    print(f"95% 置信区间 = [{lo:+.4%}, {hi:+.4%}]")
    print(f"z = {z:.4f}   p = {pval:.4f}")
    print("结论：", "显著（可全量）" if pval < 0.05 and diff > 0 else
          ("显著下降（回滚）" if pval < 0.05 and diff < 0 else "不显著（记录并关闭）"))
    print(">> 决策前必须同时检查护栏指标是否恶化。")

if __name__ == "__main__":
    main()
```

> "经复核，您在【{评分项}】的测算确实与政策原文 {文号}{条款} 不一致，是我们的规则配置错误，已于 {时间} 修正至规则版本 v{new}。我们已为您重新生成报告（原报告按快照保留可对照）。本站为第三方自测工具，**非高新技术企业认定管理机构**，结果仅供参考，最终以认定机构评审为准。给您带来的困扰我们深表歉意。"

> **话术 C（争议类，本站无误时）**：
> "经复核，您在【{评分项}】的测算依据是 {文号}{条款}（已附原文与计算过程），本站口径与政策一致。需要说明的是：本站**非认定管理机构**，结果为模拟测算，实际得分受评审专家主观判断与地方细则影响，本站从未、也不会做出"包过""保证通过"的承诺。建议您将本站报告作为内部准备参考，最终以认定机构评审结论为准。"

**预防（比预案更重要）**：
1. 5 处免责位 100% 存在（PRD §10.1），运营物料同样适用；
2. 禁用词库 CI 扫描（"包过""保证通过""官方""稳过包过""100%通过"）；
3. 结果页强制展示"保守/乐观"双档，绝不只给单点分（差异化 D1 本身即为防误判设计）；
4. 三态判定中"稳过"一档**改名为"达标概率较高"**（避免"稳"字构成暗示）—— 见 §8.6 待确认项。

## 9. V1.1 / V2.0 的增长抓手

### 9.1 账号体系上线后的 CRM 与分层运营

**分层模型（账号体系上线后立即建立）**

| 层 | 定义 | 运营目标 | 关键动作 | 指标 |
|----|------|----------|----------|------|
| **L-A 企业自评用户** | 单一企业、自评 1~2 次/年 | 完成自评 → 导出 → 订阅 | 复评提醒、政策订阅、补齐清单 | 30/90 日回访率、订阅率 |
| **L-B 高频企业用户** | ≥3 次自评 / 多方案对比 | 培育为年度习惯用户 | 年度自评提醒、方案对比推广 | 跨季复评率 |
| **L-C 代理机构顾问（R3）** | role=agency，多企业 | 批量测评 → 机构版转化 | 批量导入、方案对比、白标报告、周节拍 | 机构账号月留存、月报告产出量 |
| **L-D 园区/孵化器（V2.0）** | 园方账号 | 批量摸底园区企业 | 园区专属落地页、摸底报告 | 园区覆盖企业数 |
| **L-E 沉睡用户** | 180 天未活跃 | 召回或淘汰 | 新功能 + 政策版本升级触达 | 召回率 |

**CRM 最小能力（V1.1）**：用户标签（角色/行业/地区/达标状态/申报批次）、分群（按上述 5 层）、触达任务（按 §4.4 频控）、触达记录与退订状态。**不得**建立企业敏感数据的 CRM 字段（财务/信用代码只在产品库加密存储，CRM 层只存达标状态与行业地区等派生标签）。

### 9.2 机构版（多企业）商业化

| 项 | 设计 | 增长价值 |
|----|------|----------|
| 产品 | F-28 机构多企业工作台（≥50 家）+ F-29 协作批注 + 白标报告 | R3 用户刚需 |
| 定价（建议，需评审） | 席位订阅 ¥299~999/席/月；或按报告量 ¥19~49/份 | 未定价，待评审 |
| **增长指标** | 机构账号 ≥30 家；**机构账号贡献 WCSO 占比 ≥40%**（PRD §9 V2.0 目标） | 从"单企业低频"转为"机构高频"，**根本性改善留存结构** |
| 获客路径 | C7 代理机构合作（§2.4）：内容共创 → 内测 → 白标试用 → 付费 |
| 关键转化点 | 批量导入（F-21/F-22）是机构版最强钩子 —— 顾问导入一个客户台账后迁移成本形成 |

### 9.3 提分模拟器与材料清单（V2.0 D5/F-32）

| 功能 | 增长价值 | 预期指标影响 |
|------|----------|--------------|
| **提分模拟器**（改变量看总分变化 + 提分动作性价比排序） | **最强的二次回访理由**（对应 §4.1 W3）：用户补了软著/签了产学研后想看分数变化 | 90 日回访率 +8~12pp；方案对比使用率 ≥25% |
| **材料清单**（按诊断结果导出需准备的材料清单，分派各部门） | 从"知道差多少"到"知道准备什么"，把工具嵌入申报工作流 | 导出率 +5~8pp；留资率 +3pp |
| 联动 | 模拟器的每次"如果…"都会生成一个方案 → 自然带动 F-18 方案对比与 F-19 历史版本 | 形成使用深度正循环 |

### 9.4 小程序（仅条件触发，非承诺）

**触发条件（三条全满足才做，沿用选型报告 §5 裁定）**：
1. **移动端访问占比 > 40%**（连续 4 周监测）；
2. **存在明确的微信内分享/裂变需求**（如园区群/顾问群内传播需求被验证）；
3. 已有稳定运营人力（内容 + 社群 ≥1 FTE）。

**若触发，小程序的获客定位（不是产品复制）**：

| 项 | 定位 |
|----|------|
| 角色 | **轻量获客端**，不是完整测算端 |
| 范围 | 资格预检（8 项）+ 6 题粗测 + 结果查看 + 报告查看 |
| **明确不做** | 完整四项打分、台账录入、PDF 导出 —— **全部引回 Web**（长表单与导出在小程序内体验差，选型报告 §5 已裁定） |
| 获客逻辑 | 微信内传播 → 小程序轻量体验 → "查看完整报告/精确测算"引回 Web → Web 完成深度转化 |
| 传播机制 | 预检结果卡片分享到群（这是 Web 短链无法覆盖的微信内场景） |
| 指标 | 小程序 → Web 引回转化率（目标 ≥20%）；小程序自评完成量占总量的 ≥15%（PRD §9 V2.0） |
| 合规 | 小程序同样不得自称官方、不得承诺包过；分享卡片同样含"仅供参考" |
